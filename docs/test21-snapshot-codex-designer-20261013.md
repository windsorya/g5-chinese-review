## (a) 根因
檢查載體仍是「篩選後的散落字串」，不是完整、有位置與配對關係的審定教材。HEAD 仍先由 CR_ASK 決定哪些內容值得檢查（tests/chibank.test.js:248、278）；leaves() 丟掉欄位與例句配對；SVG 正則只讀沒有子標籤的 <text>（266–271）。補同義詞、標點或個別反例只會移動缺口；現有自檢沿用同一套篩選器，無法證明完整涵蓋。

## (b)(c) 推薦：整份審定快照＋結構斷言
可讀 JSON 快照（可附 SHA-256，但不要只留雜湊）。快照契約逐欄涵蓋：
- EXPLAIN.cr.length、卡片索引及順序；cr[i].name；cr[i].lines[j]（含長度、順序）；cr[i].examples[j].s 與 .why 保留在同一物件、保留例句順序；cr[i].task；cr[i].ask；
- cr[i].svg()：完整元素樹、所有文字子節點、所有屬性（含 aria-label、位置、樣式、可見性）；不可直接 JSON.stringify(EXPLAIN.cr)（函式會消失）；
- 卡片及例句的欄位集合、型別：新增未知欄位或缺欄直接紅。
正規化：
| 項目 | 規則 |
|---|---|
| 空白 | CRLF 統一；裁文字首尾排版空白、連續 ASCII 空白折疊；中文／標點間的排版空白忽略，英數詞界保留一格。不可把所有 \s、零寬字一律刪除 |
| Unicode | NFC；保留標點、否定字、零寬字及方向控制字，不用 NFKC |
| 順序 | 物件鍵、SVG 屬性名稱排序；陣列、元素及子節點順序不排序 |
| SVG | 用 XML parser 建樹並解碼 entity；遞迴保留子節點，對 <text> 等文字容器取完整 textContent（自然包含 <tspan>）；忽略元素間縮排；解析失敗直接紅 |
結構斷言另釘：恰有兩張卡；第一張 lines[1]／lines[6]、第二張 lines[3]／lines[4] 分別承載「不用先問」與「超出才要授權」的審定句（不再由散落字串湊 free／need）。
快照更新必須顯示差異、重新送審，不能在測試中從待測內容即時產生預期值。網站成品另由 build.py 內嵌來源產生 index.html，快照不涵蓋成品一致性。
